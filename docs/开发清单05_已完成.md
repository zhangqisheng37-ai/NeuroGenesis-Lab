# 第五阶段开发清单：核心引擎重构与性能突破 (Phase 5)

## 1. 当前项目痛点分析

在完成前四个阶段的开发后（基础网络、进化算法、混合学习引擎、向量化加速），NeuroGenesis Lab 已经具备了完整的数字生命模拟能力。但随着实验规模的扩大，当前架构暴露出以下核心痛点：

1. **复杂逻辑的向量化瓶颈**：虽然 `vectorized.py` 使用 NumPy/SciPy 极大地提升了纯张量运算的速度，但进化算法（如尸体回收、局部突变）和符号规则发现（`learning.py` 中的 `PatternMiner`）包含大量复杂的条件分支，这些逻辑难以完全向量化，导致在 Python 层面产生严重的性能回退。
2. **GIL 限制与多核利用率低**：脉冲神经网络（SNN）的事件路由和神经元状态更新天然适合并行计算，但受限于 Python 的全局解释器锁（GIL），当前引擎无法真正利用多核 CPU，导致 10k+ 神经元规模下的 Tick 耗时显著增加。
3. **内存开销与 GC 抖动**：海量脉冲事件（Spike Events）和突触连接在 Python 中以对象或大矩阵形式存在，不仅内存占用极高，且频繁的创建和销毁会引发垃圾回收（GC）停顿，导致模拟帧率（Tick Rate）不稳定。
4. **高频观测的 I/O 阻塞**：虽然实现了 gzip 压缩和日志轮转，但在高频记录（`--log-interval` 较小）时，同步的磁盘 I/O 依然会阻塞主模拟循环。

---

## 2. 第五阶段核心目标

本阶段的核心目标是**引入 Rust + Python 混合架构**，在保持 Python 顶层 API 敏捷性的同时，彻底解决底层计算和并发瓶颈，使框架具备支撑 **100k+ 神经元** 实时模拟的能力。

- **目标 1**：引入 PyO3/Maturin 构建 Rust 扩展模块 `neurogenesis_core`。
- **目标 2**：将核心的事件路由、LIF 状态更新和基础进化逻辑下沉至 Rust。
- **目标 3**：实现真正的多线程 Tick 运算（基于 Rayon）。
- **目标 4**：优化 I/O 机制，实现异步无阻塞的观测数据落盘。

## 3. 详细开发任务

### 3.1 混合架构基础设施搭建
- [x] **任务 3.1.1**：在项目中集成 `maturin` 和 `PyO3` 构建系统，更新 `pyproject.toml`。
- [x] **任务 3.1.2**：创建 `rust_src/` 目录，初始化 Rust crate `neurogenesis_core`。
- [x] **任务 3.1.3**：配置 CI/CD 管道，支持跨平台（Windows/Linux/macOS）的 Rust 扩展编译（Wheel 打包）。

### 3.2 核心计算模块下沉 (Rust 移植)
- [x] **任务 3.2.1**：在 Rust 中实现 `SimEngine` Protocol 的底层数据结构（如 `TickSnapshot`, `EngineSummary`）。
- [x] **任务 3.2.2**：使用 Rust 重写 `LIFNeuron` 和 `IzhikevichNeuron` 的核心状态更新方程（Tick 逻辑）。
- [x] **任务 3.2.3**：在 Rust 中实现高效的稀疏矩阵或邻接表，用于替代现有的突触权重存储，优化内存局部性。
- [x] **任务 3.2.4**：将事件队列（Event Queue）和脉冲路由（Spike Routing）逻辑迁移至 Rust。

### 3.3 并发与内存优化
- [x] **任务 3.3.1**：引入 Rust 的 `rayon` 库，实现神经元群组状态更新的无锁多线程并行计算。
- [x] **任务 3.3.2**：优化进化算法中的内存分配，使用对象池（Object Pool）或 Arena 分配器管理神经元和突触的生灭，消除 Python GC 带来的延迟抖动。
- [x] **任务 3.3.3**：将 `learning.py` 中计算最密集的模式挖掘（Pattern Mining）算法用 Rust 重写，通过 FFI 暴露给 Python 的 `RuleDiscovery` 模块。

### 3.4 异步 I/O 与观测性能提升
- [x] **任务 3.4.1**：重构 `logger.py` 和 `observability.py`，引入后台异步线程或 Rust 侧的异步 I/O 通道进行日志写入。
- [x] **任务 3.4.2**：实现内存中的双缓冲（Double Buffering）机制：主线程写入 Buffer A，后台线程将 Buffer B 压缩并落盘，彻底消除 I/O 阻塞。

## 4. 验收标准

1. **性能指标**：在相同硬件下，10,000 神经元规模的基准测试（`python -m neurogenesis_lab benchmark`）Tick 耗时降低至少 50%。
2. **规模突破**：能够稳定运行 100,000 神经元规模的模拟，且内存占用不超过 4GB。
3. **兼容性**：现有的所有 Python 测试用例（`pytest`）必须 100% 通过，保证底层替换对上层 API 完全透明。
4. **代码质量**：Rust 代码需通过 `cargo clippy` 检查，Python 代码保持 75% 以上的测试覆盖率。
5. **文档更新**：更新 `architecture.md`，补充 Rust 混合架构的说明和编译指南。
