# 第六阶段开发清单：代码质量治理与架构精炼 (Phase 6)

## 1. 当前项目痛点分析

在完成前五个阶段的开发后（基础网络、进化算法、混合学习引擎、长程稳定与可视化、Rust 混合架构），NeuroGenesis Lab 已具备完整的数字生命模拟能力和高性能计算基础。当前代码基线 v0.4.1，测试覆盖率 92.72%，229 个测试用例全部通过。

但随着功能的持续叠加，代码层面暴露出以下结构性问题：

1. **核心方法过长**：`Network.tick()` 113 行、`VectorizedNetwork.tick()` 188 行、`cmd_run()` 189 行，职责混杂，可读性和可维护性下降。
2. **类职责过重**：`Neuron` 类 68 个字段（动力学 + 演化 + 记忆 + 统计混杂），`Network` 类 42 个字段（配置与运行时状态未分离），违反单一职责原则。
3. **文档字符串覆盖不足**：类型注解虽 100% 覆盖，但公共 API 的 docstring 平均仅约 40%，核心方法如 `tick()`、`update()`、`emit()`、`spawn()` 缺少文档。
4. **硬编码魔法值散布**：`learning.py` 中 ASCII 码判断（48-57）、各模块中的阈值常量未提取，维护成本高。
5. **向量化引擎性能隐患**：稀疏矩阵频繁 lil ↔ csr 转换、`scheduled_inputs` 字典无过期清理机制、`connect_by_proximity()` 在大规模网络下 O(n²) 复杂度。
6. **错误处理不完善**：异步日志写入失败时可能丢失数据，`AsyncJsonlWriter.close()` 使用轮询等待，matplotlib 操作缺少异常保护。

---

## 2. 第六阶段核心目标

本阶段的核心目标是**代码质量治理与架构精炼**，在不改变外部 API 的前提下，系统性地提升代码可读性、可维护性和健壮性。

- **目标 1**：拆分超长方法，每个方法控制在 60 行以内。
- **目标 2**：重构过重类，将 `Neuron` 和 `Network` 拆分为组件化设计。
- **目标 3**：公共 API 文档字符串覆盖率从 40% 提升至 80%+。
- **目标 4**：消除硬编码魔法值，提取为命名常量。
- **目标 5**：修复性能隐患和错误处理缺陷。
- **目标 6**：测试覆盖率保持 >92%，新增重构回归测试。

## 4. 验收标准

1. **方法长度**：所有公共方法不超过 80 行，核心 `tick()` 编排方法不超过 30 行。
2. **类字段数**：`Neuron` 直接字段 ≤20（其余通过组件访问），`Network` 直接字段 ≤15。
3. **文档覆盖**：公共 API docstring 覆盖率 ≥80%（通过 `interrogate` 或手动审计）。
4. **魔法值**：代码中不存在未命名的数值常量（除 0、1、-1 等通用值外）。
5. **测试覆盖**：覆盖率保持 ≥92%，新增测试用例 ≥20 个。
6. **兼容性**：所有现有测试（229 个）100% 通过，外部 API 无破坏性变更。
7. **性能**：基准测试耗时不超过重构前基线的 110%。

## 7. 风险预警

| 风险 | 影响 | 缓解措施 |
| ---- | ---- | -------- |
| 方法拆分引入微妙行为差异 | 仿真结果不一致 | 拆分前录制基线快照，拆分后逐 tick 对比 |
| `Neuron` 组件化导致性能退化 | 属性访问增加一层间接调用 | 使用 `__slots__` 优化，基准测试验证 |
| `Network` 状态分离破坏 checkpoint 兼容 | 旧 checkpoint 无法加载 | 实现版本迁移逻辑，保留旧格式读取能力 |
| docstring 补充引入不准确描述 | 误导使用者 | 结合代码逻辑逐一审核，避免复制粘贴 |
| 常量提取遗漏关联修改点 | 运行时行为变化 | 全局搜索确认所有引用点，测试覆盖验证 |
