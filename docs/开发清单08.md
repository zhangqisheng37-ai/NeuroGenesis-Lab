# 第八阶段开发清单：高级特性与生态扩展 (Phase 8)

## 1. 当前项目现状

在完成前七个阶段的开发后，NeuroGenesis Lab 已成为一个**工程成熟、功能完整、文档齐全**的神经进化仿真研究平台。

**当前代码基线**：v0.6.0，约 350 个测试用例全部通过，总覆盖率 92.61%，源代码约 7,000 行。

**已具备能力**：
- ✅ 完整的 CI/CD 管道（多平台测试、lint、覆盖率、文档自动部署）
- ✅ 双引擎功能对等（Network + VectorizedNetwork 均支持完整演化/学习能力）
- ✅ 模块化 CLI 架构（cli/ 子包，职责清晰）
- ✅ 自动 API 文档生成（mkdocs + GitHub Pages）
- ✅ 严格类型标注（mypy strict 模式）
- ✅ 发布就绪（LICENSE、CONTRIBUTING、py.typed）

**当前短板**：
1. **缺少交互式可视化**：当前仅支持静态图表生成，无法实时观察仿真过程
2. **缺少分布式仿真能力**：单机运行限制了大规模实验（10k+ 神经元长程运行）
3. **缺少实验管理系统**：多次实验的参数、结果、对比分析依赖手动管理
4. **缺少预训练模型库**：用户需从零开始训练，无法复用已有的演化成果
5. **缺少插件系统**：扩展新神经元模型、新学习算法需要修改核心代码
6. **缺少 Web 界面**：CLI 对非技术用户不友好
7. **缺少性能分析工具**：难以定位性能瓶颈
8. **缺少社区生态**：示例库未分层（`examples/` 已有 12 个示例但无 beginner/advanced/research 结构）、无插件贡献机制

---

## 2. 第八阶段核心目标

本阶段的核心目标是**高级特性与生态扩展**，使项目从"可用的研究工具"向"活跃的开源生态"演进。

- **目标 1**：实现实时交互式可视化（WebSocket + 前端）
- **目标 2**：支持分布式仿真（多进程/多机并行）
- **目标 3**：构建实验管理系统（参数追踪、结果对比、可视化分析）
- **目标 4**：建立预训练模型库与加载机制
- **目标 5**：设计插件系统架构（动态加载、热插拔）
- **目标 6**：开发 Web 管理界面（实验配置、监控、结果查看）
- **目标 7**：集成性能分析工具（profiling、火焰图）
- **目标 8**：建立社区贡献机制（示例库、插件市场）

## 3. 详细开发任务

### P0：实时交互式可视化（最高优先级）

目标：提供实时观察仿真过程的能力，支持暂停/继续/调速。

- [ ] **P0.1**：设计 WebSocket 协议 — 定义 tick 数据推送格式、控制命令格式。
  - 消息类型：`tick_update`、`pause`、`resume`、`speed_change`、`stop`
  - 数据格式：JSON（包含神经元位置、能量、连接、放电事件）
- [ ] **P0.2**：实现 WebSocket 服务器 — 使用 `websockets` 或 `aiohttp`。
  - 新增 `src/neurogenesis_lab/server.py`
  - 支持多客户端连接
  - 集成到 CLI：`python -m neurogenesis_lab serve --port 8765`（独立服务模式）
- [ ] **P0.3**：开发前端可视化界面 — 使用 React + D3.js 或 Three.js。
  - 实时渲染神经元网络（2D/3D）
  - 显示能量、种群统计、学习规则
  - 控制面板：暂停/继续、调速、参数调整
- [ ] **P0.4**：集成到 `run` 命令 — 新增 `--live-monitor` 参数。
  - `python -m neurogenesis_lab run --live-monitor --port 8765`
  - 复用 P0.2 的 WebSocket 协议，在 run 内嵌启动服务器并打开浏览器
- [ ] **P0.5**：新增实时可视化测试 — 验证 WebSocket 连接、数据推送、控制命令。

### P1：分布式仿真支持

目标：支持多进程/多机并行，突破单机性能瓶颈。

#### 任务 P1.1：多进程并行

- [ ] **P1.1.1**：设计分布式架构 — Master-Worker 模式，Master 负责协调，Worker 负责计算。
  - 说明：优先支持 `Network` 引擎；`VectorizedNetwork` 是否支持待评估（向量化内核跨进程拆分复杂度高）。
- [ ] **P1.1.2**：实现神经元分区策略 — 按空间位置或连接密度分区。
- [ ] **P1.1.3**：实现跨进程通信 — 使用 `multiprocessing.Queue` 或 `ray`。
- [ ] **P1.1.4**：处理边界神经元 — 跨分区连接的同步机制。
- [ ] **P1.1.5**：新增 CLI 参数 — `--workers N` 指定进程数。

#### 任务 P1.2：多机并行（可选）

- [ ] **P1.2.1**：集成分布式框架 — 使用 `ray` 或 `dask`。
- [ ] **P1.2.2**：实现网络通信 — 跨机器的神经元状态同步。
- [ ] **P1.2.3**：容错机制 — Worker 失败时的恢复策略。
- [ ] **P1.2.4**：性能基准 — 对比单机 vs 多机的加速比。

### P2：实验管理系统

目标：自动追踪实验参数、结果，支持对比分析和可视化。

- [x] **P2.1**：设计实验元数据格式 — 包含配置、种子、版本、时间戳、结果摘要。
  - 首选 SQLite（`experiments.db`），支持查询和索引；JSON 作为导出/迁移格式。
  - ✅ 已实现：`src/neurogenesis_lab/experiments.py`（`ExperimentRecord` + `ExperimentStore`），字段与 `outputs/experiments/index.json` 结构对齐；`export_index()` 支持 JSON 导出；自动迁移旧原型 schema。
- [x] **P2.2**：实现实验追踪 — `run` 命令自动记录实验元数据。
  - 新增 `--experiment-name` 参数
  - 自动生成唯一实验 ID
  - ✅ 已实现：实验 ID 复用输出目录名（run_YYYYMMDD_HHMMSS_mmm）；开始时写入 running，结束时更新为 completed/failed；追踪失败时降级不影响仿真。
- [x] **P2.3**：实现实验查询 — 新增 `list` 子命令。
  - `python -m neurogenesis_lab list --filter "neurons>100"`
  - filter 语法：支持 `key op value`（op 为 `>`, `<`, `>=`, `<=`, `=`, `!=`），多条件用 `,` 或 `and` 连接。
  - 显示实验列表、参数、结果摘要
  - ✅ 已实现：`cli/list.py`，支持 `--db` / `--filter` / `--limit`；过滤键覆盖顶层字段与 summary/final_metrics 指标。
- [x] **P2.4**：实现实验对比 — 新增 `compare` 子命令。
  - `python -m neurogenesis_lab compare exp1 exp2 exp3`
  - 生成对比报告（参数差异、结果对比、可视化图表）
  - ✅ 已实现：`cli/compare.py`，输出参数差异表（仅展示取值不同的配置项，点分键）与结果指标对比表；可视化图表待 P5 Web 界面复用。
- [x] **P2.5**：实现实验删除 — 新增 `delete` 子命令。
  - `python -m neurogenesis_lab delete exp1`
  - 删除输出文件和元数据
  - ✅ 已实现：`cli/delete.py`，支持批量删除与 `--keep-files`；安全护栏：仅当输出目录名与实验 ID 一致时才删除文件。

### P3：预训练模型库

目标：提供可复用的演化成果，加速研究迭代。

**与现有 checkpoint 的关系**：`--checkpoint-interval` / `--resume-from` 用于运行中恢复；P3 的 `--save-model` / `--load-model` 面向「最终状态 + 元数据」的模型复用。可复用 checkpoint 序列化格式，扩展元数据（训练历史、Schema 版本等）。

- [ ] **P3.1**：设计模型格式 — 包含网络状态、配置、训练历史、Schema 版本。
  - 复用或扩展 checkpoint 格式（pickle），确保跨版本兼容（Schema 版本校验）。
  - 新增 `models/` 目录
- [ ] **P3.2**：实现模型保存 — 新增 `--save-model` 参数。
  - `python -m neurogenesis_lab run --save-model models/my_model.pkl`
  - 保存最终网络状态和配置
- [ ] **P3.3**：实现模型加载 — 新增 `--load-model` 参数。
  - `python -m neurogenesis_lab run --load-model models/my_model.pkl --ticks 100`
  - 从预训练模型继续演化
- [ ] **P3.4**：建立模型库 — 提供预训练模型集合。
  - `models/stable_100.pkl`：100 神经元稳定种群
  - `models/learning_50.pkl`：50 神经元学习型网络
  - `models/sparse_200.pkl`：200 神经元稀疏连接
- [ ] **P3.5**：新增模型验证 — Schema 版本校验、兼容性检查、可复现性验证（种子/配置记录）。

## 4. 验收标准

1. **实时可视化**：`python -m neurogenesis_lab run --live-monitor` 可在浏览器中实时观察仿真，支持暂停/继续/调速；tick 推送延迟 < 500ms（1000 神经元规模）。
2. **分布式仿真**：`python -m neurogenesis_lab run --workers 4` 可使用 4 个进程并行，4 进程加速比 ≥ 2x。
3. **实验管理**：`list`、`compare`、`delete` 子命令可用，实验元数据自动追踪。
4. **预训练模型**：`models/` 目录包含 ≥3 个预训练模型，`--load-model` 可正常加载，Schema 版本校验通过。
5. **插件系统**：提供 ≥2 个插件示例，`--plugin-dir` 可动态加载插件。
6. **Web 界面**：`python -m neurogenesis_lab web` 可启动 Web 服务器，提供实验配置、监控、结果查看功能。
7. **性能分析**：`--profile` 可生成性能报告和火焰图。
8. **社区生态**：示例库包含 ≥10 个案例（含分层目录），插件索引上线（GitHub Topics 或 README），至少 1 个社区渠道建立。

## 7. 风险预警

| 风险 | 影响 | 缓解措施 |
| ---- | ---- | -------- |
| WebSocket 实时推送性能瓶颈 | 高频 tick 下延迟增加 | 实现数据采样和压缩，降低推送频率 |
| 分布式仿真同步开销大 | 多进程加速比不理想 | 优化分区策略，减少跨进程通信 |
| P0 与 P5 功能重叠 | serve vs web 职责混乱 | 明确：serve 轻量可视化，web 完整管理，复用协议与组件 |
| P3 模型格式跨版本兼容 | 旧模型无法加载 | 模型内嵌 Schema 版本，加载时校验并给出迁移指引 |
| 插件系统安全风险 | 恶意插件破坏系统 | 实现沙箱隔离，限制插件权限 |
| Web 界面开发工作量大 | 延期风险 | 使用成熟的 UI 框架，复用 P0 组件 |
| 社区生态建设缓慢 | 用户参与度低 | 积极推广，提供激励机制 |
| 性能分析工具开销大 | 影响仿真性能 | 仅在需要时启用，提供轻量级模式 |
